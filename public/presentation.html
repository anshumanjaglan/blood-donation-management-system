Section 1 • Clinical Motivation

Problem Statement & Challenges

Clinical Reality: Blood has zero synthetic substitutes and a strict shelf-life of 35-42 days. In acute hemorrhage and trauma, delay of minutes often proves fatal.

01. Scattered Information

Stock figures are locked in isolated hospital registries with zero real-time public synchronization.

02. Emergency Latency

Patients' relatives are forced to make unverified phone calls and social media pleas while surgeries wait.

03. Inefficient Donor Search

No automated matching engine to filter registered voluntary donors by clinical ABO/Rh compatibility and city proximity.

04. Lack of Inventory Audits

Manual registers suffer from human errors in tracking critical threshold shortages, safe levels, and camp collections.

Section 4 • Engineering Design

Multi-Tier System Architecture

Tier 1: Presentation Layer (Frontend)

HTML5 Semantic Markup, CSS3 Modern Healthcare Palette, Vanilla ES6+ JavaScript, Chart.js Visualizations. Zero bloated frontend runtime dependencies for 100% mobile responsiveness.

Tier 2: Application Layer (Backend Microservices)

Node.js and Express.js REST APIs. Non-blocking asynchronous event loop ensures concurrent requests, emergency broadcasts, and session management operate with low latency.

Tier 3: Algorithmic Matching Layer

Clinical ABO and Rh(D) compatibility matrix combined with geographic proximity ranking (services/matchingService.js).

Tier 4: Unified Database Layer

Dual-database architecture: Production 3NF MySQL relational schema (database.sql) + zero-config embedded persistence fallback for bulletproof viva defense.

Section 5 • Data Architecture

Relational Database Design (3NF)

blood_inventory

PK: id | UK: blood_group

Tracks live units available, safe thresholds, and critical thresholds for all 8 blood groups.

donors

PK: id

Stores voluntary donor demographics, blood group, age (18-65), phone, city, availability flag, and last donation date.

blood_requests

PK: id | UK: request_code

Logs patient requirement, units needed, hospital, city, urgency, emergency flag, status, and fulfillment source.

donations

PK: id | FK: donor_id

Audit trail of whole blood units collected, donation dates, mobile camp locations, and tested hemoglobin levels.

hospitals

PK: id | UK: license_no

Registry of verified healthcare institutions, official coordinators, and bulk emergency requisitions.

admins

PK: id | UK: username

Secure credentials for Chief Administrator (Dr. Anshuman Jaglan) and hospital staff officers.

Section 6 • Algorithmic Core

Clinical ABO/Rh Compatibility Engine

Medical Compatibility Matrix

  • O- (Universal Donor): Can give red cells to all 8 blood groups (A+, A-, B+, B-, AB+, AB-, O+, O-).
  • AB+ (Universal Recipient): Can safely receive blood from any blood group.
  • Rh-D Factor Rule: Rh- individuals can only receive Rh- units; Rh+ can receive either positive or negative.

Matching Score Formulation

Score = 50 (Base) + BloodBonus + CityBonus

  • • Exact Blood Group: +30 Points
  • • Compatible Alternative: +15 Points
  • • Exact City Match: +20 Points
  • • Nearby District Match: +10 Points
  • • Eligibility Filter: Requires is_available = TRUE
